### RuleMatchConfig

![Configuration Structure](ConfigurationView.svg)

#### Purpose

`RuleMatchConfig` is a record holding the match conditions of one routing rule, read from the
`match:` block of a `rules:` entry in `.buildmark.yaml`. It is defined alongside `RuleConfig` in
`Configuration/RuleConfig.cs` and is referenced by `RuleConfig.Match`.

#### Data Model

**Label**: `List<string>` — Label values to match; the condition holds when the item's
normalized type equals any entry, compared case-insensitively; an empty list means label
matching is not applied. Get-only, initialized empty.

**WorkItemType**: `List<string>` — Work-item type values to match; the condition holds when the
item's normalized type equals any entry, compared case-insensitively; an empty list means
work-item type matching is not applied. Get-only, initialized empty.

When both lists are non-empty, both conditions must hold for the rule to match.
The list properties are never `null`; `BuildMarkConfigReader` adds the values from a `label` or
`work-item-type` key, which may be a single scalar or a sequence of scalars.

#### Key Methods

N/A — `RuleMatchConfig` is a configuration data record with no methods beyond those
auto-generated by C#.

#### Error Handling

N/A — Data record with no methods that detect or propagate errors. Invalid `match:` content is
reported by `BuildMarkConfigReader` as a `ConfigurationIssue`.

#### Dependencies

N/A — `RuleMatchConfig` has no dependencies on other units.

#### Callers

- **RuleConfig** — holds an optional `RuleMatchConfig` in its `Match` property.
- **BuildMarkConfigReader** — parses the `match:` mapping and populates `Label` and
  `WorkItemType`.
- **ItemRouter** — evaluates `Label` and `WorkItemType` against each item to select a rule.
